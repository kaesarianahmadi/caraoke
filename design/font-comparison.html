Caraoke — Font Comparison

Every lyric surface in the app, rendered at true point sizes (1 CSS px = 1 pt) in the four text faces Apple actually ships. Open in Safari on macOS: San Francisco and SF Pro Rounded are both resident, so this is the same rasterisation iOS performs.

The strings are the longest real lyric lines the app handles — the ones that wrap to two and three rows inside the widget budget. Type that looks comfortable on a short line can fall apart on a long one, so long lines are the honest test.

The face is .default, which on iOS resolves to the Text optical size below 20 pt and the Display one above it — so the widget rows render in SF Pro Text while the 28 pt lyrics page renders in SF Pro Display, with no separate handling anywhere in the code. The weight is .bold on every lyric row, hero and neighbours alike: the hierarchy is the opacity ladder (0.36–0.82), which is what lets one bold weight carry both the active line and the dimmed context without a second weight axis fighting the fade.

4 · What this changes, and what it does not

Safe to change — the budget does not move

  • Face and weight are free. LyricRowBudget.height(rows:) is pure arithmetic — rows × font + (rows−1) × lineSpacing — so swapping the face, or the weight, cannot invalidate a single height assertion in Tests/main.swift.
  • Rounded sets a little wider than SF Pro Text at the same size. A long line wraps perhaps one word sooner; the three-row hero allowance the surfaces already carry absorbs that, which is why 18 pt did not need to move.
  • Every surface picks it up at once. One LyricType.font(size:weight:) helper is now the only way a lyric font gets built — the rows, the placeholder lines, "No lyrics found for this song" and the Dynamic Island's expanded hero all go through it.
  • Dynamic Type still works. A system font scales; a bundled font would not. Rounded is a Font.Design on the system font, not a different typeface — it keeps every accessibility behaviour, including the larger accessibility sizes.

Left alone deliberately

  • Size. 18 pt is what makes layoutFontIs18 pass, and the row budgets are asserted against it. The face change is the one that alters the feel; moving the size at the same time would confound the two and only a device could tell them apart.
  • Chrome, controls and metrics. Standard San Francisco throughout. The rounded face is a content marker, not a theme — the same split Apple Music Sing and Podcasts use.
  • Icon glyphs. SF Symbols carry their own optical weight; they are not type and are untouched.

Measurement note: the point sizes above are real — 18 pt, 14 pt, 158 pt — because a browser at default zoom maps 1 px to 1 pt on a non-Retina logical grid. If the comparison is being read on a scaled display, set the page to 100% before judging the weights.
